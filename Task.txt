ЗАДАЧА: РАЗРАБОТКА ГРАФОВОЙ БАЗЫ ДАННЫХ ДЛЯ МУЗЕЯ
Необходимо спроектировать и реализовать графовую базу данных на платформе MS SQL Server для моделирования работы музея: управления экспонатами, залами и гидами.

СУЩНОСТИ (УЗЛЫ / NODES):
Exhibit (экспонат) — содержит идентификатор ExhibitID, название Name, автора Artist, год создания Year и тип ExhibitType.
Примеры: «Мона Лиза», «Давид», «Подсолнухи», «Девятый вал».
Типы экспонатов: портрет, пейзаж, скульптура, натюрморт.

Hall (зал) — содержит идентификатор HallID, название HallName и площадь SquareMeters.
Примеры: «Зал итальянского Ренессанса», «Зал скульптуры», «Зал импрессионистов».

Guide (гид) — содержит идентификатор GuideID, ФИО FullName, стаж работы ExperienceYears и языки Language.
Примеры: «Анна Иванова» (5 лет, русский+английский), «Пётр Смирнов» (12 лет, русский+французский).

СВЯЗИ (РЁБРА / EDGES):
ExhibitInHall (экспонат находится в зале) — направленная связь от Exhibit к Hall.
Атрибуты: PlacementDate (дата размещения), IsPermanent (постоянная ли выставка).
Один экспонат может находиться в нескольких залах (например, временная выставка).

GuideLeadsHall (гид ведёт экскурсию в зале) — направленная связь от Guide к Hall.
Атрибуты: Schedule (расписание), MaxGroupSize (максимальный размер группы).
Один гид может вести экскурсии в разных залах.

GuideKnowsExhibit (гид знает экспонат) — направленная связь от Guide к Exhibit.
Атрибуты: KnowledgeLevel (уровень знаний: основное, детальное, экспертное), LastUpdated (дата последнего обновления знаний).

ОГРАНИЧЕНИЯ (CONNECTION CONSTRAINT):
Связь ExhibitInHall может соединять только вершины типа Exhibit и Hall.

Связь GuideLeadsHall может соединять только вершины типа Guide и Hall.

Связь GuideKnowsExhibit может соединять только вершины типа Guide и Exhibit.

ЗАПОЛНЕНИЕ ДАННЫМИ:
Таблица Exhibit: 10 записей (различные экспонаты: портреты, пейзажи, скульптуры, натюрморты).

Таблица Hall: 10 записей (различные тематические залы).

Таблица Guide: 10 записей (гиды с разным стажем и языками).

Таблица ExhibitInHall: 11 записей (каждый экспонат привязан к залу, один экспонат может быть в двух залах — постоянном и временном).

Таблица GuideLeadsHall: 11 записей (каждый гид ведёт экскурсии в 1-2 залах).

Таблица GuideKnowsExhibit: 14 записей (гиды знают различные экспонаты с разными уровнями знаний).

ЦЕЛИ РАБОТЫ:
Реализовать графовую базу данных с использованием синтаксиса AS NODE и AS EDGE в MS SQL Server.

Написать 5 различных запросов с использованием функции MATCH для анализа цепочек взаимодействия.
Примеры:
Найти всех гидов, которые водят экскурсии по залам, где выставлены экспонаты Леонардо да Винчи.
Найти гидов, которые знают экспонаты, выставленные в залах, где работает Анна Иванова.
Найти все скульптуры и гидов, которые их знают (с информацией о залах, где работают гиды).
Найти пары гидов, которые работают в одном зале и оба знают хотя бы один общий экспонат из этого зала.
Найти гидов, которые знают экспонаты на временных выставках.

Написать 2 запроса с использованием SHORTEST_PATH:
С шаблоном + (один или более шагов): найти кратчайший путь от гида до всех достижимых экспонатов.
С шаблоном {1,3} (от 1 до 3 шагов): найти кратчайший путь от скульптуры до всех гидов, которые могут до неё провести.

Визуализировать полученный граф в Power BI с помощью Force-Directed Graph (отобразить узлы: гиды, залы, экспонаты; рёбра: связи между ними).

Создать диаграммы графа в diagrams.net (3 страницы: схема данных, примеры запросов MATCH, примеры запросов SHORTEST_PATH).
